1) Phase Bridge and Scope Guardrails

Task Planning is the execution-planning bridge that translates canonical Design contracts into sequenced implementation and increment-level delivery outcomes. Scope is constrained to MVP capabilities: Gmail ingestion, event detection/extraction, event persistence, duplicate prevention, reminder scheduling, and Google Calendar sync.

Scope guardrail: WhatsApp/SMS are documented only as future-phase placeholders and must not become dependencies in MVP milestones or critical path sequencing.

Canonical Dependencies

  • docs/02-design/runtime-flow.md (runtime lifecycle authority)
  • docs/02-design/reliability-policy.md (retry/state/failure policy authority)
  • docs/00-product/traceability-matrix.md (cross-phase traceability authority)

Execution Readiness Preconditions

  • OAuth + provider sandbox readiness for Gmail and Calendar
  • Migration path for events/reminders/sync failure metadata
  • Deterministic extraction/dedupe fixtures for validation
  • Baseline telemetry for intake, extraction, schedule, and sync

4) Task Breakdown and Dependency Logic

The task catalog groups WS1–WS6 into implementation, validation, observability/reliability, and documentation-sync work so readiness is evidence-driven rather than feature-only.

Engineering Task Coverage

  • Ingestion/auth integration
  • Extraction parsing + confidence gating
  • Persistence + dedupe controls
  • Schedule generation/re-computation
  • Calendar create/update + retry/failure-state handling

Validation + Reliability Coverage

  • Fixture-driven parser/dedupe checks
  • E2E critical path scenarios (happy + failure)
  • Retry-policy conformance and terminal-state recording
  • Telemetry and alert coverage for key transitions
  • Documentation synchronization and HTML regeneration

7) Assumptions, Constraints, Open Questions

Assumptions

  • Extraction fixtures adequately represent MVP email variability.
  • Calendar provider quotas can support MVP validation and rollout.

Constraints

  • MVP excludes WhatsApp/SMS implementation dependencies.
  • Retry/terminal-state behavior must follow reliability policy.

Open Questions

  • Threshold and path for mandatory low-confidence manual review.
  • Escalation policy for sync failure classes in MVP operations.
  • Initial sync-latency SLO target beyond acceptance baseline.
