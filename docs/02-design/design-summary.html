1) Architecture Scope and Boundaries

MVP architecture includes Gmail ingestion, event extraction, event persistence, duplicate prevention, schedule generation, and Google Calendar synchronization. This is the active system boundary for V1 runtime behavior.

MVP in-scope runtime

  • Gmail API ingestion as the only source channel.
  • Extraction confidence + normalized canonical event records.
  • Dedupe/idempotency boundaries before fan-out.
  • Scheduling defaults (4h, 1h, 15m).
  • Google Calendar sync with persisted outcomes.

Post-MVP extensibility only

  • WhatsApp delivery channel (future phase).
  • SMS delivery channel (future phase).
  • Future adapters must reuse Event Service idempotency + observability contracts.
MVP channel guardrail: WhatsApp/SMS are not active architecture commitments for MVP runtime and must not appear as deployed/operational components in implementation planning.
Source: architecture.md (Sections 3-4)

3) Data and Sequence Flow Design

Email → Calendar canonical flow

  • Ingest message and preserve correlation identifiers.
  • Extract structured candidate with confidence score.
  • Run dedupe/idempotency check before persistence fan-out.
  • Persist canonical event, generate schedule records, enqueue calendar sync.
  • Persist sync outcome and emit observability signals.

Sequence narratives represented

  • Primary MVP path with duplicate branch behavior.
  • Retry loop with timeout enforcement and attempt metadata persistence.
  • Terminal-failure transition with operator remediation signal.
  • Safe replay/reprocessing path with idempotency protection.
Sequence coverage summary: Design markdown explicitly includes primary runtime flow, reliability loop behavior, and safe reprocessing boundaries aligned to FR-09/FR-10/FR-11 and US-07/US-09/US-11.

5) Deployment Notes, Assumptions, Trade-offs, and Open Questions

Deployment/environment notes

  • Dev/staging/prod isolation for credentials and observability scope.
  • Environment-scoped secret management and rotation.
  • Policy-governed retry and queue tuning by environment.
  • Production runbooks must include terminal sync-failure procedures.

Assumptions and trade-offs

  • MVP source channel is Gmail only.
  • MVP continuity target is Google Calendar only.
  • Reliability depth is prioritized over multi-channel breadth.
  • Deferring WhatsApp/SMS reduces integration risk for V1.
Open questions highlighted in design markdown: low-confidence operator intervention depth, retry-attempt policy tuning by environment, and paging-vs-dashboard criteria for specific terminal failure reasons.
Source: architecture.md (Section 11), sequence-flows.md
