Technical Specification Summary (MVP-Aligned)

Markdown source of truth: docs/01-tech-spec/*.md.

MVP Scope Boundary

  • Gmail ingestion, event detection/extraction, persistence, duplicate prevention
  • Reminder schedule generation (4h / 1h / 15m)
  • Google Calendar sync as the only active downstream capability in MVP
  • WhatsApp and SMS remain post-MVP and operationally disabled in MVP

Canonical Sync State Contract

PENDING, IN_PROGRESS, SYNCED, FAILED_RETRYABLE, FAILED_TERMINAL

Any transition to FAILED_TERMINAL persists failure_reason, provider_status, and last_attempt_at.

Idempotency and Conflict Outcomes

ScenarioPersisted StatusAPI-visible Outcome
Duplicate enqueue attemptExisting PENDING/IN_PROGRESS retainedReplay-safe 202 with dedupe metadata
Repeated sync attemptIN_PROGRESS retained unless retry executesNo duplicate provider create
Retry exhaustionFAILED_TERMINAL + terminal metadataTerminal status visible for remediation
Already-synced replaySYNCED retainedalreadySynced=true response metadata

Integration MVP Execution Boundary

  • Active in MVP: Google OAuth, Gmail ingestion, Google Calendar sync
  • Disabled in MVP: WhatsApp/SMS adapters and provider runbooks
  • Post-MVP providers are excluded from MVP SLOs and support scope

Measurable Security / NFR Controls

  • Monthly rolling-window availability verification (excluding planned maintenance)
  • Quarterly access review evidence
  • Dependency scan release gate for unresolved high/critical vulnerabilities
  • Annual restore drill evidence

Failure Path Diagram Coverage

  • Calendar sync transient failure -> retry -> success sequence
  • Calendar sync terminal failure -> persisted terminal status -> operator remediation sequence
