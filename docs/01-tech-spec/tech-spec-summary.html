Technical Specification — Stakeholder Summary

Premium consolidated presentation of the markdown source of truth under docs/01-tech-spec. This view is optimized for architecture and delivery reviews while preserving explicit traceability to source files.

Source of truth: Markdown Scope: V1 MVP Audience: Engineering + Technical Stakeholders

Architecture

Modular monolith with queue-based async boundaries, designed for future service extraction.

Reliability

Idempotent processing, retries, dead-letter policies, and auditable lifecycle tracking.

Security

OAuth hardening, least privilege, encryption of delegated tokens, and immutable audit logs.

Scalability

Horizontally scalable workers, managed data services, and observability-led operations.

Frontend Technical Specification

Defines feature-module structure, routing, server-state strategy, validation, and diagnostics for `apps/web` without mixing visual design concerns.

  • Feature modules: auth, preferences, events, settings, observability
  • State strategy: TanStack Query + localized UI state + React Hook Form
  • Technical quality gates: accessibility baseline (WCAG 2.1 AA), responsiveness, performance budgets

UI/UX reference boundary is explicitly documented; `docs/02-ui-ux` is currently missing and tracked as a gap.

Source: frontend-spec.md

Backend Technical Specification

Defines strict layered architecture and domain workflow ownership for auth, ingestion, extraction, dedupe, scheduling, dispatch, and sync.

Lifecycle: Request validation → service orchestration → transactional persistence → async side effects via queue.

Database Schema Specification

PostgreSQL schema defines identity, ingestion, event lifecycle, reminder delivery, integrations, and audit lineage.

  • Duplicate prevention: `event_dedupe_keys` unique fingerprint per user
  • Dispatch traceability: `reminders` + `delivery_attempts`
  • Operational lineage: `audit_logs` + `job_runs`

Source: db-schema.md and diagrams/data-model-diagram.md
