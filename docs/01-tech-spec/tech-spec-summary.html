1) Technical Overview and Lifecycle Narrative

MVP System Boundary

Committed MVP pipeline is Google OAuth + Gmail ingestion + event extraction/persistence + reminder scheduling + Google Calendar sync. Messaging providers are explicitly deferred post-MVP.

Core Lifecycle

Detect event email, normalize content, enforce dedupe key, persist event and reminders, then execute calendar sync with stateful retry/terminal-failure handling.

Architecture Intent

API, workers, and scheduler split responsibilities for reliability and observability while preserving idempotent behavior across ingest and sync stages.

Reliability controls:
  • Exponential backoff for calendar sync (5s, 10s, 30s, 60s, 120s), max 5 attempts.
  • Workflow ordering enforces duplicate prevention before downstream sync side effects.
  • Error taxonomy and observability hooks include trace IDs, structured status fields, and terminal-failure metadata persistence.

3) API Contracts and MVP Exposure Rules

Contract Standards

  • JSON over HTTPS; UTC ISO-8601 timestamps.
  • Versioned base path: /api/v1.
  • Consistent success/error envelopes with traceId.

Auth & Authorization

  • Session cookie model for user APIs.
  • Signed token/HMAC for internal callbacks.
  • User-owned resource access only in MVP.

Capability Boundary

  • Active in MVP: calendarSync.
  • sms and whatsapp are post-MVP reserved.
  • Reserved capabilities may be omitted or explicitly false with metadata flags.

4) Data Model, Integrity Rules, and Channel Guardrails

The schema defines persistent entities for auth, source ingestion, event normalization, dedupe, reminders, calendar sync records, audit logs, and job runs.

Key integrity requirements:
  • Transactional persistence across event and dedupe boundaries to prevent duplicate downstream behavior.
  • MVP channel enforcement guardrail keeps non-calendar delivery paths disabled.
  • Audit and retention fields support traceability, operational investigation, and compliance posture.
Sources: docs/01-tech-spec/integration-spec.md, diagrams/sequence-diagram-placeholders.md

5) Integrations and Failure-Path Coverage

MVP Integrations

  • Google OAuth for authorization.
  • Gmail API for source ingestion.
  • Google Calendar API for sync execution.

Failure Handling

  • Transient failures transition to FAILED_RETRYABLE with retry policy.
  • Terminal failures persist structured metadata for remediation.
  • Sequence placeholders include retry-success and terminal-remediation paths.

Post-MVP Integrations

  • WhatsApp and SMS provider hooks are documented as deferred placeholders.
  • Deferred providers are out of MVP support/SLO scope.
