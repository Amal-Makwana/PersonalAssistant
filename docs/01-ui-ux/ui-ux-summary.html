1) UX Overview, Scope, and Outcomes

The UI/UX layer operationalizes the product contract into a reliable review-and-confirm journey: detect candidate events, review extraction confidence, prevent duplicates, schedule reminders, and synchronize with Google Calendar in MVP.

Committed MVP UX Outcomes

  • Trust-first onboarding with explicit Google auth and Gmail permission clarity.
  • Low-friction review for extracted event details and confidence visibility.
  • Predictable reminder setup defaults and change management.
  • Observable Google Calendar sync status with retry/recovery paths.

Scope Guardrails

  • Active MVP capability includes Gmail ingestion and Google Calendar sync.
  • WhatsApp/SMS appear only as future-phase references, not active UI runtime dependency.
  • System prioritizes extraction quality and duplicate suppression before channel expansion.

3) User Flow Catalog and Interaction-State Logic

Core Flow Set (F1-F8)

  • F1 first-time setup and account connection.
  • F2 extracted event review and confirm reminder.
  • F3 global reminder defaults update.
  • F4 diagnostics review and recovery flow.
  • F5-F8 support duplicate management, sync validation, and account/session controls.

Flow States + Failure Paths

  • All primary flows include loading, empty, validation, success, and error pathways.
  • Calendar sync failure and retry visibility is treated as first-class UX requirement.
  • Permission-denied and integration-disconnected paths require explicit user guidance.
Flow governance: operationally risky transitions (extraction ambiguity, duplicate suppression, sync retry) are intentionally surfaced rather than hidden to preserve trust.

5) Wireframe Specification Summary

S01-S02 Onboarding

Trust-forward OAuth and step-based setup with sticky actions, sync testing, and contextual guidance blocks.

9) Assumptions, Gaps, and Open Questions

Assumptions

  • Google OAuth and Gmail/Calendar connectivity remain available and healthy for MVP flow completion.
  • Confidence scoring thresholds are provided by backend contracts and rendered consistently in UI states.
  • Role/permission complexity remains limited to MVP user/operator paths documented in current flow set.

Gaps / Open Questions

  • Potential future expansion for messaging-channel UI is intentionally deferred and must not alter MVP IA.
  • Any unresolved copy/empty-state language for failure remediation should be finalized in markdown sources before implementation freeze.
  • Additional accessibility audit evidence (screen-reader walkthrough artifacts) should be attached during delivery validation.
Scope control reminder: WhatsApp/SMS remain post-MVP roadmap items and should not appear as active controls in MVP screens beyond future-state references.
