1) Execution Planning Scope and Ownership

Execution Planning is now the canonical pre-development planning phase. It owns decomposition, sequencing, backlog/dependencies, quality gating, rollout planning, and readiness criteria. Design remains canonical for architecture, runtime contracts, and reliability semantics.

Scope boundary: MVP execution targets Gmail ingestion, extraction, persistence, dedupe, reminder scheduling, and Google Calendar sync continuity. WhatsApp/SMS remain post-MVP roadmap items.
Source: build-plan.md

2) Build Plan: Milestones and Increment Logic

Milestone 1

Intake and canonical event baseline, including ingestion path and persistence foundations with traceability updates.

Milestone 2

Reminder orchestration and operator visibility with confidence handling and diagnostics-readiness checks.

Milestone 3

Calendar sync reliability completion and release hardening with rollback readiness sign-off.

Increment model uses thin vertical slices: A) intake to persistence, B) schedule orchestration, C) sync + remediation.
Source: backlog-and-dependencies.md

5) Rollout, Rollback, and Execution Readiness

Release planning uses progressive rollout (internal -> pilot -> broad) with promotion tied to quality gates and reliability thresholds.

Operational Readiness

  • Dashboards: throughput, confidence, scheduling, sync outcomes.
  • Alerting by severity aligned to reliability policy.
  • Runbook co-ownership across engineering and operations.

Rollback Controls

  • Triggers: sustained sync failures, persistence integrity risks, scheduler SLA breach.
  • Actions: cohort pinning, deployment revert, data consistency checks, recovery validation.
  • Approvers: Engineering Manager, QA Lead, Product Owner.
